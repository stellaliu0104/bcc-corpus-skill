# 未来功能展望（按师门价值排序）

> 现状基线：三模式技能（对话检索/导入语料/完整界面）+ 交互式 HTML/xlsx/csv 全量导出 + 首用引导存储目录。
> 以下为候选功能，按"语言学价值 × 文科生易用性 ÷ 实现成本"排序，供与师门讨论后立项。

## 第一梯队（语言学刚需，建议尽快做）

### 1. 搭配强度统计（互信息 MI / 卡方 / t 值）⭐⭐⭐
- **痛点**：现在只有原始频次，"很好"824 次和"很难"572 次其实都不算典型搭配——频次高只说明两个词都高频。语言学判断搭配典型性需要 MI/卡方。
- **方案**：`search.py` 加 `collocate` 子命令：给定节点词（如"很"），统计右侧所有搭配词的 MI/卡方/频次表，导出同现有三格式。
- **成本**：中（需全库词频做期望频计算，可预计算缓存）。**建议先请师门确认用哪个统计量**（审核清单新增项）。

### 2. 按语料来源分组对比 ⭐⭐⭐
- **痛点**：语料混了演讲/电视剧对白/访谈，"很 vs 非常"的结论其实被语料构成干扰。师门一定会问"单看演讲语料呢？"
- **方案**：先由师门给 779 个文件定**来源分类表**（文件名→标签，Excel 填一遍，正好给维护语料的师妹做）；`search.py` 支持 `--group 演讲` 按文件子集检索；compare 支持跨组对比（演讲 vs 对白）。
- **成本**：低（引擎天然按文件组织，分组=文件名过滤）。

### 3. HTML 结果页增强 ⭐⭐
- 关键词高亮（现在左右文是纯文本）
- 左文/右文**正则筛选**（如只看右文以"地"开头的）
- 按来源文件筛选（依赖功能 2 的标签）
- 翻页/虚拟滚动（5000 条也不卡）
- **成本**：低-中，纯前端模板改动。

## 第二梯队（体验优化）

### 4. Word 论文表格导出
- 直接生成师门论文可粘贴的三线表（word 格式模板：词/频次/占比 + 表注自动带统计口径）。
- 文科生最常用的最终交付物是 Word，省去从 Excel 手动排版。

### 5. 检索历史与一键复跑
- 会话内记住最近 N 次检索（query/时间/结果文件路径），"再跑一次上次的"即可复现；跨会话存 data/history.json。
- 成本低；师门对照不同检索式结果时很省事。

### 6. 常见问题库自动扩充管线
- agent 每次成功翻译后，把"问题→检索式"自动追加到 data/qa_log.json；维护者定期筛好的进 examples.md → **技能越用越准**的闭环落地。
- 注意需用户同意（隐私：问题文本会落盘）。

### 7. 语料更新自动化
- 师妹拖新文件进"语料收件箱"文件夹（配置项）→ 下次检索自动发现未索引文件并提示导入 → 一句话完成增量入库+索引重建。
- 现在的 `--rebuild` 是全量重建，增量更友好。

## 第三梯队（远期/依赖外部条件）

### 8. 多语料库切换
- `--corpus` 配置化（config.json 里存多个命名语料库），支持"师门演讲库""公开 BCC 库"切换对比。依赖功能 2 的标签体系。

### 9. 语音语料转写入库
- 音频文件 → 转写（Whisper 或师门现有转写流程）→ 自动进导入管线。师门若有田野录音是刚需，需先确认转写质量和成本。

### 10. 审核清单在线化
- 语言学审核清单变成技能内交互流程：agent 逐条问师妹、即时回填词表——降低"填表"门槛。
- 依赖 WorkBuddy 的多轮交互质量实测。

## 明确不做（避免过度工程）

- ❌ 用户管理/权限系统（师门是熟人网络，微信群协调即可）
- ❌ 云端同步（隐私+成本，zip 分发已够用）
- ❌ 自建 Web 服务（WorkBuddy 本身就是入口，重复建设）
